# معلم خصوصی هوش مصنوعی ایران (Iran AI Tutor)

سکوی معلم خصوصی فارسی مبتنی بر کتاب‌های درسی رسمی ایران. هدف محصول، پاسخ‌گویی مستند به کتاب، فصل و شمارهٔ صفحهٔ چاپی است؛ اگر منبع قابل‌اتکا در کتاب‌های بارگذاری‌شده پیدا نشود، سیستم باید از حدس‌زدن خودداری کند.

پروژه مرحله‌ای ساخته می‌شود. بک‌اند RAG، APIهای متن/تصویر/صوت، آزمون زمان‌دار، پنل توسعهٔ ادمین و رابط وب دانش‌آموز نسخهٔ اولیه دارند؛ **این پروژه هنوز محصول کامل تولیدی نیست.** ورودی‌های تصویری/صوتی، آزمون، گفت‌وگو، حل تمرین و طراحی سؤال در حالت نمایشی قابل‌تست‌اند؛ modeهای آموزشی هنوز با مدل واقعی ارزیابی نشده‌اند. کنکور واقعاً چندپایه، احراز هویت پیامکی، پلن/سهمیه و مجوزهای ادمین کامل نشده‌اند. آزمون کیفیت مدل‌ها و transcription واقعی باید با ارائه‌دهندهٔ پیکربندی‌شده جداگانه انجام شود.

> APIهای ادمین و معلم هنوز احراز هویت ندارند و فقط برای توسعهٔ محلی‌اند. آن‌ها را روی اینترنت عمومی منتشر نکنید.

## ساختار اصلی

| مسیر | توضیح |
|---|---|
| `.kilocode/rules/architecture.md` | قواعد معماری، فازها و رفتار معلم |
| `docker-compose.yml` | PostgreSQL، Qdrant و Redis |
| `.env.example` | تنظیمات نمونهٔ Docker؛ فایل واقعی `.env` را نسازید/کامیت نکنید |
| `backend/` | FastAPI، پردازش PDF، مدل‌های داده و آزمون‌ها |
| `backend/storage/` | PDFهای آپلودشده، تصاویر و خروجی پردازش؛ در Git ثبت نمی‌شود |
| `frontend/` | Next.js RTL، کلاس دانش‌آموز، پرسش چندرسانه‌ای، آزمون و پنل توسعهٔ ادمین |

## راه‌اندازی برای تست و عیب‌یابی

برای تست رابط و مسیرهای API بدون کلید سرویس‌دهنده، ابتدا **حالت نمایشی آفلاین** را اجرا کنید. این حالت SQLite و دادهٔ مصنوعی دارد؛ هیچ API بیرونی را صدا نمی‌زند و پاسخ‌هایش برای آموزش واقعی/ارزیابی مدل مناسب نیستند. کتاب نمونه با برچسب «کتاب آزمایشی» به‌صورت خودکار ساخته می‌شود.

```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.demo.example .env
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

در پنجرهٔ ترمینال دوم:

```bash
cd frontend
npm install
npm run dev
```

سپس `http://localhost:3000` را باز کنید؛ پایهٔ دوازدهم، رشتهٔ ریاضی‌فیزیک و کتاب «فیزیک ۳ — کتاب آزمایشی» را انتخاب کنید. `/docs` مستندات API و `/admin` ابزار آزمایشی بارگذاری/بازبینی‌اند. فایل پایگاه‌داده و داده‌های نمونه محلی و نادیده‌گرفته‌شده توسط Git هستند. در حالت نمایشی، آپلود PDF مسیر پردازش را می‌آزماید اما OCR واقعی نمی‌کند و صفحه را نیازمند بازبینی علامت می‌زند.

**این حالت فقط برای توسعهٔ محلی است.** متن‌ها، پاسخ‌های صوت/تصویر و سؤال‌های آزمون از fixture قطعی می‌آیند؛ این حالت، کیفیت مدل واقعی را نمی‌سنجد. برای آزمون مدل/پردازش واقعی و آماده‌سازی سرویس، ادامهٔ همین راهنما را اجرا کنید.

## راه‌اندازی سرویس واقعی در Ubuntu / WSL2

پیش‌نیازها: Docker Desktop با WSL integration، Python 3.11+ و اطلاعات سرویس‌های سازگار با APIهای موردنیاز.

### ۱. زیرساخت

از ریشهٔ مخزن:

```bash
cp .env.example .env
# در صورت نیاز POSTGRES_PASSWORD را در .env عوض کنید.
docker compose up -d
docker compose ps
```

سرویس‌ها باید وضعیت `healthy` داشته باشند. پورت‌های دیتابیس فقط روی loopback منتشر شده‌اند:

| سرویس | پورت |
|---|---:|
| PostgreSQL | 5432 |
| Qdrant HTTP / gRPC | 6333 / 6334 |
| Redis | 6379 |

### ۲. بک‌اند

```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
```

در `backend/.env` مقدارهای `LLM_BASE_URL`، `LLM_API_KEY`، نام مدل‌های `VISION_MODEL_*` و `TUTOR_MODEL` را با اطلاعات سرویس خودتان پر کنید. برای RAG، سرویس انتخابی باید API embedding هم ارائه کند؛ در صورت متفاوت بودن ارائه‌دهنده، `EMBEDDING_BASE_URL` و `EMBEDDING_API_KEY` را جداگانه تنظیم کنید. `EMBEDDING_DIMENSION` باید با بُعد بردار مدل embedding یکی باشد. مقدار `DATABASE_URL` نمونه با تنظیمات پیش‌فرض ریشه هماهنگ است؛ اگر رمز PostgreSQL را عوض کردید، همین‌جا هم آن را عوض کنید.

سپس مهاجرت و API را اجرا کنید:

```bash
alembic upgrade head
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

مستندات API محلی: <http://127.0.0.1:8000/docs>

APIهای انتخاب محتوای درسی برای رابط کاربری:

```text
GET /api/v1/curriculum/grades
GET /api/v1/curriculum/majors
GET /api/v1/curriculum/books?grade_number=12&major_code=math_physics
```

### ۳. آزمون‌ها

آزمون‌های واحد به `.env`، کلید API یا دیتابیس واقعی نیاز ندارند:

```bash
cd backend
source .venv/bin/activate
pytest -q
```

اسکریپت `scripts/test_ingest.py` ابزار مقایسهٔ مدل‌هاست، نه مجموعهٔ تست pytest؛ برای جلوگیری از اجرای تصادفی آن، pytest فقط مسیر `tests/` را جمع‌آوری می‌کند.

## پردازش کتاب — فاز ۱

برای پایه‌های ۱۰ تا ۱۲، کد رشته الزامی است. PDF را در مسیر دلخواه نگه دارید؛ فایل PDF و خروجی‌های پردازش وارد Git نمی‌شوند.

```bash
cd backend
source .venv/bin/activate
python scripts/ingest_book.py \
  --pdf /path/to/physics12.pdf \
  --grade 12 --major math_physics --title "فیزیک ۳" \
  --start 5 --end 9
```

گزینه‌های مهم:

| گزینه | کاربرد |
|---|---|
| `--dry-run` | فقط برنامهٔ کار را نشان می‌دهد؛ هیچ رندر، فراخوانی مدل یا نوشتنی ندارد |
| `--force` | صفحات انتخاب‌شده را دوباره پردازش می‌کند |
| `--only-failed` | فقط صفحات ناموفق را دوباره تلاش می‌کند |
| `--overwrite-human` | اجازهٔ بازنویسی صفحات اصلاح‌شده توسط انسان را می‌دهد |

خروجی‌ها در `backend/storage/books/<book_id>/` قرار می‌گیرند: JSON/Markdown، تصاویر صفحات و پیش‌نمایش. برای صفحه‌های نامطمئن، خروجی نیازمند بازبینی است و نباید بدون بررسی انسانی به‌عنوان استخراج قطعی تلقی شود.

پیش‌نمایش API پس از پردازش:

```text
GET /api/v1/admin/books/{book_id}/preview?status=all&page_from=2&page_to=5
```

اصلاح دستی صفحه:

```text
PUT /api/v1/admin/books/{book_id}/pages/{pdf_page_index}
{"markdown_content":"...", "printed_page_number":3}
```

### مقایسهٔ دو مدل بینایی

این دستور فقط خروجی مقایسه و HTML پیش‌نمایش می‌سازد و در پایگاه‌داده چیزی ثبت نمی‌کند:

```bash
python scripts/test_ingest.py \
  --pdf /path/to/physics12.pdf --start 2 --end 5 --model both
```

خروجی در `backend/storage/books/<book_id>/compare.html` ساخته می‌شود. این کار API مصرف می‌کند و ممکن است هزینه داشته باشد.

## RAG و پرسش از کتاب — فاز ۲ (نسخهٔ اولیه)

پس از اینکه پردازش کتاب را تمام کردید و صفحه‌های قابل‌اعتماد را در پایگاه‌داده دارید، صفحه‌های دارای وضعیت `done` را در Qdrant ایندکس کنید. صفحه‌های `needs_review` تا زمان بازبینی و تأیید انسانی وارد جست‌وجو نمی‌شوند:

```bash
cd backend
source .venv/bin/activate
python scripts/index_book.py --book-id 1 --batch-size 32
```

این دستور برای embedding API و Qdrant در حال اجرا نیاز به دسترسی دارد و هزینهٔ embedding ممکن است داشته باشد. برای جست‌وجو، API فقط پایه، رشته و کتاب انتخاب‌شده را می‌پذیرد و فیلتر را در سمت سرور اعمال می‌کند:

```bash
curl -X POST http://127.0.0.1:8000/api/v1/tutor/ask \
  -H 'Content-Type: application/json' \
  -d '{"query":"شیب نمودار مکان-زمان چه مفهومی دارد؟","grade_number":12,"major_code":"math_physics","book_id":1}'
```

در درخواست متنی، فیلد اختیاری `mode` یکی از `tutor`، `problem_solver` یا `question_designer` است؛ انتخاب همین حالت در APIهای تصویر و صوت هم با فیلد multipart `mode` انجام می‌شود. پاسخ شامل متن و فهرست منابع بازیابی‌شده است. PostgreSQL و Qdrant به‌صورت ترکیبی جست‌وجو می‌کنند؛ اگر مسیر برداری در دسترس نباشد، نتیجهٔ متنی PostgreSQL می‌تواند استفاده شود. اگر هیچ منبعی پیدا نشود، مدل زبانی فراخوانی نمی‌شود و پاسخ حدس‌زده نخواهد شد.

## پرسش تصویری و صوتی — فاز ۳ (API اولیه)

هر دو endpoint از پایه/رشته/کتاب انتخاب‌شده استفاده می‌کنند و سؤال را فقط با همان کتاب به RAG می‌فرستند. فایل رسانه‌ای برای این درخواست پردازش می‌شود و در این endpointها ذخیرهٔ دائمی نمی‌شود.

- تصویر: `POST /api/v1/tutor/ask-image` با `multipart/form-data` شامل `image`, `grade_number`, `book_id`, `major_code` (در پایه‌های ۱ تا ۹ خالی) و اختیاری `top_k`. فرمت JPEG/PNG/WebP و سقف ۱۰ MiB.
- صدا: `POST /api/v1/tutor/ask-audio` با همین فیلدها و `audio`؛ سقف ۲۵ MiB. باید `SPEECH_TO_TEXT_MODEL` تنظیم شود. اگر سرویس صوتی با LLM اصلی فرق دارد، `AUDIO_BASE_URL` و `AUDIO_API_KEY` را هم تنظیم کنید. بسیاری از endpointهای سازگار با OpenAI قابلیت transcription ندارند؛ پشتیبانی واقعی سرویس انتخابی را جداگانه بررسی کنید.

### API آزمون زمان‌دار

```text
POST /api/v1/exams
GET  /api/v1/exams/{exam_id}
POST /api/v1/exams/{exam_id}/submit
```

ساخت آزمون به `grade_number`, `major_code`, `book_id`, `question_count`, `time_limit_minutes`, `exam_type` و اختیاری `chapter_title` نیاز دارد. پاسخ آغاز آزمون **کلید و توضیح جواب‌ها را افشا نمی‌کند**؛ تصحیح سمت سرور انجام می‌شود و کارنامه پس از ثبت پاسخ‌ها برمی‌گردد. نوع `konkoor` نمرهٔ درصدی با جریمهٔ یک‌سوم پاسخ غلط می‌دهد؛ نوع `final` فعلاً آزمون چهارگزینه‌ای با نمره از ۲۰ است. تصحیح پاسخ تشریحی هنوز پیاده‌سازی نشده است.

## رابط وب دانش‌آموز و پنل توسعه

رابط Next.js در پوشهٔ `frontend/` اجرا می‌شود و درخواست‌های `/api/*` را از سمت سرور به بک‌اند می‌فرستد:

```bash
cd frontend
npm install
# در صورت نیاز: BACKEND_ORIGIN=http://127.0.0.1:8000
npm run dev
```

صفحهٔ اصلی شامل انتخاب پایه/رشته/کتاب، پرسش متنی، بارگذاری تصویر، ضبط صدا و آزمون زمان‌دار با گزینه‌های کلیکی و کارنامه است. `/admin` پنل توسعه‌ای برای بارگذاری و پردازش PDF و مشاهدهٔ وضعیت/پیش‌نمایش است. مسیر `BACKEND_ORIGIN` باید به نشانی backend که از خود فرآیند Next.js قابل‌دسترسی است اشاره کند؛ در محیط‌های preview یا استقرار آن را مطابق شبکهٔ همان محیط تنظیم کنید.

**هشدار امنیتی:** APIهای ادمین و معلم هنوز احراز هویت/مجوز ندارند. پنل `/admin` فقط ابزار توسعه است؛ بک‌اند را به اینترنت عمومی متصل نکنید تا لایهٔ دسترسی امن پیاده‌سازی شود. تاریخچهٔ گفت‌وگو و حساب کاربری نیز هنوز وجود ندارد.
